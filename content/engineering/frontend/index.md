# Frontend

Frontend offers two complementary paths: decisions that remain useful across frameworks, followed by guidance for the language and framework selected by the project.

## Technology-Independent Design

| Need | Start Here |
| --- | --- |
| Organize an application by domain and behavior | [Modular Architecture](./modular-architecture) |
| Choose between direct contracts, ViewModels and adapters | [UI/API Contracts](./ui-api-contracts) |

## Implementation Profiles

| Profile | Coverage |
| --- | --- |
| [TypeScript](./typescript) | Strict typing, contracts, naming, dates and type organization. |
| [Vue](./vue/) | Vue 3, Composition API, components, Pinia, composables, structure and Storybook. |

Start with the relevant design decision, then apply the stack profile. The brief comparisons with React, Angular and other frameworks in Modular Architecture are not full implementation profiles.

Agents should adapt example names and folders to the repository. Testing strategy belongs to [Quality](/quality/); public identifiers follow the canonical Engineering guidance.

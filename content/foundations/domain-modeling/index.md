# Domain Modeling

Domain-Driven Design helps represent complex behavior with explicit boundaries and vocabulary. It does not require applying every pattern, and it does not dictate a structure such as Vertical Slice Architecture.

## Progressive Path

1. [Bounded Contexts](./bounded-contexts): ownership of meanings and models.
2. [Entities and Value Objects](./entities-and-value-objects): identity and immutable values.
3. [Aggregates](./aggregates): invariants and classical consistency.
4. [Dynamic Consistency Boundaries](./dynamic-consistency-boundaries): boundaries defined by behavior.

The [broad DDD reference](./domain-driven-design-reference) keeps examples and historical decisions while these pages are the canonical conceptual sources.

# Plan Review 03 - Global Exception Handler for C# HTTP APIs

## Reason for Review

The developer requested clearer C# API guidance for using a global exception handler to map domain errors to Problem Details, so Minimal API endpoints do not repeat error-mapping branches.

## Decision

Recommend a global ASP.NET Core exception handler for domain and application exceptions in C# HTTP APIs.

The handler should:

- map domain exceptions to HTTP status codes;
- write RFC 9457 Problem Details responses;
- include stable top-level `code` values;
- sanitize unexpected errors;
- keep endpoints focused on binding, mediation and successful response construction.

## Impact

- Update the C# notes in `technologies/backend/api-design.md`.
- Replace the Minimal API example with a thinner endpoint and a centralized `IExceptionHandler` example.
- Keep endpoint metadata documenting known Problem Details responses.
- Record execution in a new phase.

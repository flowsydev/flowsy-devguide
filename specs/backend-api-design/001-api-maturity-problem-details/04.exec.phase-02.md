# Execution Phase 02 - Draft API Design Guidance

## Phase Scope

Created the public guidance for practical HTTP API design maturity.

## Changes Made

- Created `technologies/backend/api-design.md`.
- Documented the Richardson Maturity Model as a teaching model, not a standard.
- Recommended Richardson Level 2 as the practical minimum baseline for most HTTP APIs.
- Added resource-oriented route guidance and examples using general open source domains.
- Added HTTP method guidance based on RFC 9110 semantics.
- Added a compact status-code decision table for common API outcomes.
- Clarified that Level 3 hypermedia controls are contextual and optional.
- Added REST terminology guidance to avoid treating Level 2 as full REST compliance.

## Validation Evidence

Content was reviewed for:

- Title Case headings.
- General community and open source examples.
- Accurate distinction between standards and teaching models.
- No organization-specific terminology.

Build validation is recorded in Phase 06.

## Notes

- The guidance uses `HTTP API`, `resource-oriented API` and `REST-informed API` as default terms.
- REST architectural constraints are referenced without converting the page into a REST certification checklist.

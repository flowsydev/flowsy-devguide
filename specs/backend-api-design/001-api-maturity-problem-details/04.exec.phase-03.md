# Execution Phase 03 - Draft Problem Details Guidance

## Phase Scope

Added RFC 9457 Problem Details guidance to the new API design page.

## Changes Made

- Documented RFC 9457 as the current Problem Details standard that obsoletes RFC 7807.
- Added `application/problem+json` response guidance.
- Documented the core members:
  - `type`
  - `title`
  - `status`
  - `detail`
  - `instance`
- Added top-level `code` guidance as an extension for stable application problem categories.
- Added a validation error example using an `errors` extension array.
- Recommended `pointer` for JSON Pointer references and optional item-level stable `code` values for member-specific machine-readable validation behavior.
- Added traceability guidance for `traceId`, `correlationId` and `requestId`.
- Added security guidance to avoid leaking stack traces, secrets, infrastructure details or unnecessary personal data.
- Added OpenAPI documentation notes for known success and error responses.

## Validation Evidence

Content was checked against:

- RFC 9457 Problem Details.
- RFC 9110 HTTP semantics.
- OpenAPI Specification references.

Build validation is recorded in Phase 06.

## Notes

- The validation error shape uses extension members rather than a custom envelope that competes with RFC 9457.
- Top-level `code` does not replace HTTP `status`; it complements it for application-level decisions.
- The traceability guidance avoids decorative identifiers by requiring operational searchability.

# Update Discovery Requirement Templates - Analysis

## Current State

Discovery documentation includes multiple artifact types for strategy, analysis, architecture, delivery and validation. Requirement-oriented templates need consistent language so teams can distinguish needs, requirements, use cases, business rules and validation artifacts.

## Findings

- Requirements should describe what must be true, not implementation details.
- Acceptance criteria should be testable and reviewable.
- Validation artifacts should connect requirements to observable evidence.
- Examples should use neutral product or platform domains.

## Proposed Approach

Adjust templates and surrounding guidance to make artifact intent clearer while keeping Markdown lightweight.

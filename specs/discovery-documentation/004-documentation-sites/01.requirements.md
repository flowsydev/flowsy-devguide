# Sección de Recomendaciones para Sitios de Documentación con VitePress

## Objetivo

Agregar una sección bajo `/discovery/documentation/` que reúna recomendaciones prácticas para crear sitios de documentación de proyectos de software usando VitePress, alineadas con el modelo de capas disciplinarias ya documentado en esta guía.

## Problema o Necesidad

La guía documenta qué artefactos producir y cómo estructurarlos, pero no orienta sobre cómo publicar esa documentación como sitio web. Los equipos que adoptan el modelo de capas disciplinarias frecuentemente llegan a la misma pregunta: ¿con qué herramienta conviene construir el sitio y cómo se configura? Esa decisión se resuelve hoy de forma ad hoc en cada proyecto.

VitePress es la herramienta recomendada para documentación de proyectos: es la misma que usa esta guía, es de bajo mantenimiento, produce sitios estáticos y se integra bien con repositorios Git. Documentar sus convenciones de uso en este mismo sitio cierra la brecha entre "qué documentar" y "cómo publicarlo".

## Alcance

**Incluido:**

- Crear una carpeta `layers` bajo `discovery/documentation/`
- Mover `analysis`, `architecture`, `delivery`, `strategy`, `validation`, `index.md` y `writing-guidelines.md` de `discovery/documentation/` a `discovery/documentation/layers` y actualizar todos los enlaces
- Actualizar la sección `Folder Structure` de `discovery/documentation/layers/index.md` para que la estructura propuesta agrupe `analysis`, `architecture`, `delivery`, `strategy` y `validation` bajo una nueva carpeta `layers`. Además, ordernar las carpetas y archivos alfabéticamente como lo haría un explorador de archivos.
- Agregar una sección `static-site-generators` bajo `discovery/documentation/` con un archivo `index.md` que incluya una breve introducción a los generadores de sitios estáticos
- Agregar un nuevo archivo `index.md` bajo `discovery/documentation/` como introducción a `layers` y `static-site-generators`
- Agregar un archivo `vitepress.md` bajo `discovery/documentation/static-site-generators/` referenciada desde `discovery/documentation/static-site-generators/index.md` que incluya:
  - Subsección de inicio rápido: cómo inicializar un proyecto VitePress desde cero (`npm create vitepress@latest`), estructura de carpetas mínima y primer build:

  ```sh
  mkdir my-project-docs
  cd my-project-docs
  npm init -y
  npm add -D vitepress@latest
  npx vitepress init
  ```

  ```text
  ┌  Welcome to VitePress!
  │
  ◇  Where should VitePress initialize the config?
  │  ./
  │
  ◇  Site title:
  │  My Awesome Project
  │
  ◇  Site description:
  │  A VitePress Site
  │
  ◇  Theme:
  │  Default Theme + Customization
  │
  ◇  Use TypeScript for config and theme files?
  │  Yes
  │
  ◇  Add VitePress npm scripts to package.json?
  │  Yes
  │
  └  Done! Now run npm run docs:dev and start writing.
  
  Tips:
  - Since you've chosen to customize the theme, you should also explicitly install vue as a dev dependency.
  ```

  ```sh
  npm add -D vue
  npm run docs:dev
  ```

  - Subsección de configuración base: convenciones para `config.mts` (título, descripción, `nav`, `sidebar`, `themeConfig`), uso de variables CSS para paleta de marca con colores primario, secundario y terciario, así como archivos `index.md` como portada del sitio.
  - Subsección de estructura disciplinaria: cómo adaptar la estructura de carpetas recomendada en `discovery/documentation/layers/index.md` (Folder Structure) a un sitio VitePress real, incluyendo registro de rutas en el sidebar y navbar superior con criterios para dividir secciones en grupos colapsables. Incluir también instrucciones para implementar un interceptor para la navegación, para mantener expandido únicamente el grupo de navegación que contiene el enlace de la página actual.
  - Subsección de layouts y componentes: cuándo usar el layout `home` de VitePress, cuándo crear layouts personalizados, y cómo registrar componentes Vue globales en `.vitepress/theme/index.ts`.
  - Subsección de plugins recomendados que incluya instrucciones para instalar y configurar los paquetes `mermaid` y `vitepress-plugin-mermaid` para visualizar diagramas.
  - Subsección de despliegue: opciones de publicación (GitHub Pages, Netlify, servidor estático), con configuración de `base` en `config.mts` y flujo básico de CI/CD con GitHub Actions.
  - Referencias a la documentación oficial de VitePress y a ejemplos internos (esta misma guía, rentacar-docs).

**Excluido:**

- Implementación de búsqueda con Algolia u otras integraciones de terceros que requieran credenciales o configuración externa.
- Guías para Docusaurus, Starlight, MkDocs u otras herramientas de documentación.
- Automatización de generación de artefactos o scaffolding de proyectos.
- Temas visuales personalizados más allá de la paleta de marca con variables CSS.
- Configuración de multi-tenancy o internacionalización (i18n).

## Criterios de Aceptación

- La sección `static-site-generators` aparece en el sidebar y en la navegación del sitio bajo `discovery/documentation/`.
- La página índice de la sección (`/discovery/documentation/static-site-generators/index.md`) usa el layout `section-home` y enlaza a todas sus subsecciones.
- Cada subsección tiene un propósito claro, instrucciones aplicables sin ambigüedad y al menos un ejemplo de código o estructura de carpetas.
- Los ejemplos de `config.mts` son válidos para VitePress 1.x y compilan sin errores.
- El contenido es coherente con las convenciones editoriales de `writing-guidelines.md` (tono, terminología, títulos, Markdown).
- El sitio compila sin errores con `npm run docs:build` tras incorporar la nueva sección.

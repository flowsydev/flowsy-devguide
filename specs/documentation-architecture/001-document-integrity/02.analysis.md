# 001 — Analysis

## Problem

VitePress build succeeds even when custom-layout frontmatter `link` fields point to missing paths. Layer landings under Discovery Documentation omit `/layers/` in template links. Context guides and Testing pages contain consecutive duplicates and folder-name drift (`navigation/` vs `routing/`, `state/` vs `stores/`).

## Evidence

- Invalid declarations toward template destinations that require `/layers/`.
- `frontend-vue-feature-set.md` lags modular architecture conventions already recorded in the changelog.
- Testing examples and Vue context references repeat consecutively.
- Section maps under Technologies omit pages already present in the sidebar, such as Backend Design Baseline and Error Handling.

## Options Considered

| Option | Pros | Cons |
| --- | --- | --- |
| Fix defects only | Low risk; unblocks later phases | Leaves taxonomy problems in place |
| Fix and move in one change | Faster perceived progress | Mixes integrity with relocation; hard to review |
| Defer validator | Less immediate work | Build continues to hide navigation defects |

## Decision

Fix integrity defects and add `docs:validate` before any relocation. Keep public routes stable so later phases can rely on a clean link baseline.

## Risks

- Incomplete map updates leave orphan perception in landings.
- Over-broad validator rules could fail on intentional external or empty anchors.

# 002 — Analysis

## Problem

Without declared ownership, later moves will carry contradictions forward: dual ID schemes, sparse frontmatter, and cross-cutting topics restated in many places.

## Evidence

- Layers guidance and templates disagree on whether IDs translate with language.
- Most narrative pages lack frontmatter while landings and context guides use specialized fields.
- Date/time, errors and Outbox are explained in many places with no declared owner.
- Long pages mix concept, practice, implementation and example.

## Options Considered

| Option | Pros | Cons |
| --- | --- | --- |
| Publish governance before moves | Relocation inherits consistency | Delays visible tree changes |
| Move first, govern later | Faster visual progress | Rework when policies conflict |
| Force identical frontmatter on all pages | Uniform metadata | Overfits templates and bridges |

## Decision

Publish `documentation-governance.md` with taxonomy, English slugs, host-independent bridges, frontmatter contracts, the English ID catalog and the canonical matrix. Classify overloaded pages for work line 006.

## Risks

- Consuming projects may hold historical ID codes; transition must be documented, not silent.
- Over-classifying pages as “split” could create fragments without intent.

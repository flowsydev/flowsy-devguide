# 004 — Promote Documentation and Quality

## Intent

Make Documentation and Quality first-class top-level areas, separating them from Discovery, Technologies and AI-Assisted Development.

## Audience

Readers looking for project documentation, repository docs, work specs, publishing tools and testing guidance.

## Requirements

1. Create Documentation and Quality main landings.
2. Move project artifacts and VitePress under Documentation.
3. Move repository documentation under Documentation.
4. Move the public Specs-Driven Development guide under Documentation (keep internal `specs/` as the work record).
5. Move the Testing block under Quality.
6. Update navigation, links and context guides; add bridges for old routes; avoid full content copies; record visible moves in `CHANGELOG.md`.
7. Do not split moved pages yet; do not reorganize Backend, Data, Messaging or Frontend yet.

## Out of Scope

- Splitting Error Handling, DDD, Minimal APIs, Vue, VitePress detail or migration tools (006).
- Engineering cross-cutting consolidation (007).
- Final README/AGENTS sync (008).

## Acceptance Criteria

- Documentation and Quality are reachable from the top bar.
- No duplicated normative pages exist between old and new routes except explicit bridges.
- Historical links resolve via bridges or clear redirects.
- Internal `specs/` remain excluded from the build.

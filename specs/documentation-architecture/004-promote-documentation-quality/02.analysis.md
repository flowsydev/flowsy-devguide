# 004 — Analysis

## Problem

Project documentation and VitePress live under `discovery/documentation/`. Repository documentation sits under Conventions. Specs-Driven Development lives under AI though it is useful beyond agents. Testing is coherent but buried under Technologies.

## Evidence

- Delivery, architecture and repository docs are not discovery techniques.
- VitePress is a publishing tool, not a discovery method.
- Specs workflow is operational repository documentation shared by people and agents.
- Testing taxonomy already fits a Quality top-level area.

## Options Considered

| Option | Pros | Cons |
| --- | --- | --- |
| Move + bridges | Clear ownership; preserves bookmarks | Temporary bridge files |
| Label-only promotion | No file moves | Physical tree still misleads contributors |
| Copy to new routes | Easy rollback | Drift between duplicates |

## Decision

Move families to `content/documentation/` and `content/quality/`, leave host-independent bridges on previous routes and retarget context guides and navigation in the same delivery.

## Risks

- Absolute and relative links in moved trees break if not updated together.
- Context-guide frontmatter paths may lag canonical sources.

# 005 — Reorganize Engineering

## Intent

Organize technical guides under Engineering with clear ownership for Backend, Data, Messaging, Frontend, Security and Cross-Cutting.

## Audience

Implementers and maintainers looking for design and stack guidance.

## Requirements

1. Create an Engineering landing and contextual navigation.
2. Keep Backend for design baseline, architectures, APIs, reliability and .NET.
3. Promote Data and Migrations out of Backend into Data.
4. Group EDA, Event Sourcing and Kafka/Redpanda event store under Messaging.
5. Keep Frontend progression from Modular Architecture to Vue.
6. Create Security and Cross-Cutting homes; extract dependency safety from repository docs into Security.
7. Add bridges for previous `/technologies/**` routes; avoid full technical duplication; update CHANGELOG and context guides.
8. Do not split DDD, Minimal APIs or Vue yet; do not fully consolidate date/time or Outbox yet.

## Out of Scope

- Progressive page splits (006).
- Full cross-cutting profile slimming (007).
- Final operational sync (008).

## Acceptance Criteria

- Data and Messaging do not require entering through Backend first.
- Engine-specific pages link a common policy and focus on real differences.
- Backend has a clear path from conceptual design to .NET implementation.
- Frontend keeps one recommended physical structure per stack.
- Previous Technologies routes remain as bridges.

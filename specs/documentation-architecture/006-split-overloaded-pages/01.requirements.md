# 006 — Split Overloaded Pages

## Intent

Split pages that mix concept, practice, implementation and example into progressive journeys with stable landings and old-route compatibility.

## Audience

Readers who need one intent without walking a thousand-line mixed guide.

## Requirements

Split, in order:

1. Error Handling
2. Domain-Driven Design
3. C# Minimal APIs
4. Vue Ecosystem
5. Project Documentation
6. Specs-Driven Development
7. VitePress
8. Migration Tools and Strategies

Additional rules:

- Each split produces a landing, reading path and cross-links; previous routes become landing, canonical or bridge.
- Do not duplicate normative blocks; keep copyable examples.
- Minimal APIs reduce Mediator vs direct duplication.
- DDD stops owning VSA and persistence as DDD concepts.
- Vue moves agent skills to the AI context guide and testing ownership to Quality.

## Out of Scope

- Full cross-cutting profile consolidation beyond what the split requires (007).
- Operational README/AGENTS final sync (008).

## Acceptance Criteria

- Each new page declares purpose and reading path.
- Sub-area landings order resulting pages.
- Extended references are marked non-normative where retained.
- Complete examples remain reachable from the rules they illustrate.

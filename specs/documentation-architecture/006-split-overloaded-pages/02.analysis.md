# 006 — Analysis

## Problem

Several pages exceed several hundred lines and change audience mid-document. Length is a signal, not the sole criterion; splits must follow intent and audience.

## Evidence

- Error Handling owns Outbox, validation placement and messaging resilience.
- DDD owns VSA `State`/`StateHandler` and persistence conventions.
- Minimal APIs and Vue Ecosystem combine rules with full examples and agent policy.
- Project docs, SDD, VitePress and migration tools mix vision, workflow, reference and recipes.

## Options Considered

| Option | Pros | Cons |
| --- | --- | --- |
| Split by intent into progressive tours | Clear reading paths | More pages to navigate |
| Keep monoliths with TOC only | Fewer files | Intent shifts remain |
| Delete long references | Smaller tree | Loses copyable detail |

## Decision

Create progressive canonical tours and retain long-form pages as `type: reference` behind them when the detail remains useful. One subphase per source page.

## Risks

- Broken anchors after splits.
- Creating tiny fragments without real intent.
- Leaving agent skills or testing guidance on stack pages.

# 007 — Consolidate Cross-Cutting Topics

## Intent

Establish one canonical source per cross-cutting decision; turn stack pages into application profiles that link the canonical and keep only local deltas.

## Audience

Authors updating shared policies and stack-specific mappings.

## Requirements

1. Consolidate Date/Time; Auditing and Validity; Public Identifiers; Errors / Validation / Invariants; Outbox and Reliable Delivery; Testing strategy; example naming versus real artifacts; agent skills by stack.
2. Define consumer profiles for API, C#, Vue, relational modeling, engines, messaging and testing.
3. Do not delete useful stack-specific detail; do not re-move taxonomy; do not change technical behavior without evidence.
4. Reserve full operational sync for 008.

## Out of Scope

- README/AGENTS final rewrite (008).
- Mermaid bundling changes.
- New architectural topics beyond the approved matrix.

## Acceptance Criteria

- A cross-cutting policy change requires editing one conceptual page and, only if mapping changes, the affected profiles.
- Each stack profile links its canonical policy.
- Profiles do not contradict each other.
- Writing Guidelines own fictitious-name rules; AI context guides own skill lists.

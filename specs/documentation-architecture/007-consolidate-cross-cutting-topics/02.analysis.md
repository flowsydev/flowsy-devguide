# 007 — Analysis

## Problem

Even after splits, stack and engine pages still restate full shared policies. Without profile discipline, drift returns.

## Evidence

- Date/time repeats across Backend, API, C#, Vue, modeling, three engines and Testing.
- Errors repeat across architectures, APIs, Minimal APIs, EDA and Event Sourcing.
- Outbox appears as pattern, transactional rule and worker implementation.
- Example-name guidance repeats on multiple technical pages.
- Agent skills still risk living on stack pages.

## Options Considered

| Option | Pros | Cons |
| --- | --- | --- |
| Canonical + short profiles | Single policy owner | Requires disciplined linking |
| Keep full restatement per stack | Self-contained pages | Drift and contradictions |
| Delete all local detail | Minimal duplication | Loses useful stack deltas |

## Decision

Publish and enforce the governance matrix: framework-neutral canonical pages plus profiles that keep only types, APIs, precision, constraints and examples. Engines keep type/precision/function deltas only.

## Risks

- Over-trimming removes needed local guidance.
- Command vs consumer idempotency confusion if Outbox ownership is unclear.

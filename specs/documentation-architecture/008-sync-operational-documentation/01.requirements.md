# 008 — Sync Operational Documentation

## Intent

Close the migration so public content, navigation, operational docs and validators describe the same final architecture.

## Audience

Repository maintainers and contributors adding new pages after migration.

## Requirements

1. Update `README.md` and `AGENTS.md` to the final tree and `srcDir: './content'`.
2. Complete `CHANGELOG.md` for remaining visible moves.
3. Create or update a compact documentation contribution guide.
4. Review landings, navigation, context guides and operational references.
5. Retire temporary bridges only when an equivalent redirect exists; typically keep bridges.
6. Final audit: routes, orphans, metadata and canonical sources.
7. Record Mermaid `manualChunks` as separate non-blocking debt.
8. Do not commit, tag or publish by inference; do not rewrite historical specs for aesthetics; do not edit `.vitepress/dist/`; do not expand architecture beyond prior specs.

## Out of Scope

- New thematic areas beyond the approved taxonomy.
- Bundling optimization beyond registering debt.
- Silent renumbering of consumer project artifact IDs.

## Acceptance Criteria

- README, AGENTS, VitePress config and the physical tree describe the same structure.
- Build and link validation succeed.
- No orphan public pages remain.
- `docs/` and `specs/` stay out of public navigation.
- Mermaid debt is recorded under `docs/technical-debt.md`.

# 008 — Analysis

## Problem

README and AGENTS lag the `content/` layout during migration. Mid-migration operational rewrites create churn. Historical `specs/` should stay intact; `docs/` and `specs/` must remain unpublished.

## Evidence

- Operational docs previously described root-level Discovery/Technologies trees without `content/`.
- Contribution guidance is needed so new pages follow governance.
- Final audit may surface out-of-scope items that must be recorded, not silently expanded.

## Options Considered

| Option | Pros | Cons |
| --- | --- | --- |
| Sync operational docs only at the end | Minimal churn | Temporary drift during migration |
| Update README every phase | Always accurate | Noisy diffs; duplicate work |
| Remove all bridges at close | Cleaner tree | Breaks bookmarks without hosting redirects |

## Decision

Perform full operational sync at close-out. Keep host-independent bridges. Register Mermaid `manualChunks` as non-blocking debt. Do not rewrite historical execution records for aesthetics.

## Risks

- Accidental edits to `.vitepress/dist/` or historical specs.
- Orphan pages if navigation coverage is incomplete.
- Premature bridge removal without equivalent redirects.

# Unit, Integration and End-to-End Testing Guidelines by Stack - Requirements

## Objective

Add practical testing guidance for the technology stacks documented in Flowsy DevGuide, covering unit tests, integration tests, end-to-end tests and validation evidence.

## Need

The guide documents backend, frontend, database and architecture conventions, but testing guidance should be easier to compare across stacks. Teams need consistent criteria for naming, organization, isolation, data setup, evidence and execution without ignoring ecosystem-specific conventions.

## Scope

- Identify documented stacks under `technologies/`.
- Research official documentation for languages, frameworks, SDKs, CLIs and test runners.
- Add a testing section under `technologies/testing/`.
- Cover C#/.NET, TypeScript/Vue, PostgreSQL, database migrations and event-driven systems.
- Link the guidance from relevant index and AI context pages.
- Register the visible change in `CHANGELOG.md`.

## Acceptance Criteria

- Testing guidance is organized by test type and by stack.
- Recommendations distinguish unit, integration and end-to-end tests.
- Guidance includes evidence and reporting expectations.
- Examples are open-source-friendly and not organization-specific.
- `npm run docs:build` succeeds.

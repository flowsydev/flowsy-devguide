# Unit, Integration and End-to-End Testing Guidelines by Stack - Analysis

## Current State

Flowsy DevGuide includes conventions for C#, TypeScript, Vue, PostgreSQL, backend architecture, frontend modular architecture and database migrations. Testing guidance needs a dedicated structure that connects these topics.

## Findings

- Testing strategy should start with purpose: fast feedback, integration confidence, user journey confidence and evidence.
- C#/.NET guidance should fit common test project organization and runner behavior.
- TypeScript/Vue guidance should cover unit, component and browser-level tests.
- PostgreSQL and migration testing should focus on repeatability, compatibility and data safety.
- Event-driven systems need contract, handler and integration testing.
- Evidence should be concise and reproducible.

## Constraints

- Prefer official documentation and widely adopted ecosystem practices.
- Avoid prescribing a single runner when a project already has a supported stack.
- Do not use production data in examples.
- Keep examples generic and community-oriented.

## Proposed Structure

- Testing index with the overall strategy.
- Pages for unit tests, integration tests, end-to-end tests, evidence and reporting.
- Stack-specific pages for C#/.NET, TypeScript/Vue, PostgreSQL, migrations and event-driven systems.

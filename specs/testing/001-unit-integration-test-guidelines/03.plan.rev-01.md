# Unit, Integration and End-to-End Testing Guidelines by Stack - Plan Review 01

## Review Questions

### Should the guide require one testing framework per stack?

Decision: No. Recommend ecosystem-aligned options and tell teams to follow the repository's established runner when it already provides good signal.

### Should end-to-end testing be documented as mandatory?

Decision: No. End-to-end tests are recommended for critical user or consumer journeys, not every change.

### Should database migrations have separate testing guidance?

Decision: Yes. Migration validation has distinct risks: ordering, repeatability, compatibility, rollback strategy and data preservation.
